# Changelog

All notable changes to claude-pokemon will be documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) — Semver.

## [Unreleased]

### Changed

- **HTTP unifié + diagnostics + défense anti-injection terminal** (nettoyage post-audit). Nouveau `shared/src/http.ts` : `httpJson` (résultat discriminé `ok/network/parse` avec status + détail réel) remplace les **6 wrappers fetch divergents** (arena/live/auth/entry — null vs `{}` vs marqueurs : un DNS down, un timeout, un 500 et du JSON pourri étaient indistinguables). Les messages `*_failed` affichent enfin une **vraie raison** (`network: ECONNREFUSED…`, `http 502: réponse non-JSON`) au lieu de `{}`. **`POKEMON_DEBUG=1`** trace chaque requête (méthode, URL, status/erreur) sur stderr — premier chemin de diagnostic du CLI. Sécurité : `sanitizeForTerminal` strip les caractères de contrôle (ESC/OSC — injection de titre, clipboard OSC52…) de **toutes les chaînes contrôlées par le serveur** avant affichage brut (noms du leaderboard/battle/opponents, corps d'erreur, états live) — défense en profondeur au-dessus de la validation charset côté worker.

### Fixed

- **Hints de moves live dédupliqués — bug de dérive corrigé** (nettoyage post-audit). `live.ts` embarquait ses **propres tables privées** stage/moves (copie du bash) qui avaient déjà divergé des tables canoniques du package (`charizard-megay` absent → hints faux à Lv.100, que le worker pouvait rejeter). Les hints utilisent désormais **`movesForParticipant`** — la logique exacte que le worker valide (sets curatés starters + learnsets pour les wilds) ; ~80 lignes de tables dupliquées supprimées. Au passage : constantes ANSI partagées (`render/ansi.ts`, 7 fichiers dédupliqués) et le set `KNOWN` du dispatcher est **dérivé des tables de routage** (plus de 3e liste manuelle qui pouvait oublier une sous-commande → vue main silencieuse).

- **Rendu dé-fossilisé : les bugs bash « gelés » sont corrigés** (nettoyage post-audit). Le portage R3c reproduisait les bugs de bash octet par octet (l'oracle a disparu — le moteur est la source de vérité, autant qu'elle soit juste) : **`printf` passe au padding par caractères** (`%-22s` alignait « Évoli » un cran trop court par accent) et **ne tronque plus sur une conversion invalide** — le `stats.tired_warning` s'affichait `context >=90` en avalant même le saut de ligne suivant ; il affiche enfin `context >=90% pendant 7 ticks. Faire /clear pour reset.` Le bandeau « blessé » émettait le **texte littéral `\033[91m`** (bug de quoting bash) → vraie couleur rouge. L'historique d'évolution `Lv.null … null` et les dates de roster `null` → placeholders propres (`?`). Le `depuis %s` du header main et les libellés du recap (`battle won`/`rencontré` mélangés FR/EN en dur) passent par l'i18n (4 nouvelles clés FR/EN). Champ mort `scriptName` supprimé du contexte de rendu. Fixtures + goldens régénérés (13 fichiers — diffs inspectés = exactement les fixes ci-dessus).
- **Régression : l'auto-submit des stats est restauré** (nettoyage post-audit). Le portage Node du statusline avait perdu `_pokemon_maybe_autosubmit` (le commentaire du code disait lui-même « must be added before that switch » — la bascule a eu lieu sans). Conséquence : plus aucun push automatique vers le leaderboard/arène. Nouveau `shared/src/autosubmit.ts` (`planAutoSubmit`, pur + testé) : opt-in, cooldown 24h (`last_stats_submit_at` stampé dans le save avant l'écriture atomique unique), **POST détaché** depuis le statusline (enfant Node `unref()` ≤5s — zéro blocage du hot path, miroir du `curl &` bash). Bonus : le payload auto utilise désormais `buildSubmitPayload` canonique (le clone bash avait dérivé — bio/pins manquaient).
- **Garde anti-perte de données : un `state.json` corrompu est fatal** (nettoyage post-audit). Avant : un save illisible (édition manuelle, disque) était lu comme `{}` → le tick le « migrait » en œuf neuf → **écrasait le compagnon sans prévenir**. Désormais `entry-io.ts` distingue *absent* (OK : premier run) de *corrompu* (fatal) : le statusline affiche `⚠ pokemon: state.json corrompu…` sans rien écrire, `pokemon.mjs` sort en erreur 1 avec le message de réparation/restore. Idem pour `data.json`. La seam de test `POKEMON_NOW_EPOCH` est validée (une valeur invalide retombe sur l'horloge réelle au lieu de crasher). Couvert par `entry-guards.bats` (5 cas, dont le tir auto-submit réel + cooldown) + 3 vitest.

### Changed

- **Le domaine est enfin typé : `PokemonState` / `PokemonData`** (nettoyage post-audit). Nouveau `shared/src/state-types.ts` (~230 l) : le contrat complet des deux documents persistés — `state.json` (save : compagnon, équipe/PC, pokédex, sessions, événements, stats lifetime…) et `data.json` (config + contenu : lignées, wild_pool, items, saisons…). Les **chemins de mutation** (`tick.ts`, `collection.ts`, `commands.ts` — ceux qui écrivent les sauvegardes) abandonnent `type Json = any` pour ces types stricts : un typo de champ est désormais une **erreur de compilation**, plus une corruption silencieuse de save. Exporté dans l'API publique du package (consommable par api/ et web/). Zéro dérive comportementale (goldens + fixtures inchangés). Au passage, deux bugs latents NaN corrigés (`total_shinies += 1` et `xp_bonus` sur champ absent). Le reste (`arena`/`live`/`auth`/`share`/render) sera converti avec leurs refontes respectives.

### Removed

- **Hygiène infra (nettoyage post-audit)** : `shared/dist` sort de git (1,1 Mo de build commité — son seul consommateur était le submodule du repo legacy ; le `prepare: tsc` le régénère à chaque `npm ci`) ; suppression des lockfiles morts `api/package-lock.json` (antérieur au monorepo, ne contenait même pas `claude-pokemon-shared`) et `shared/package-lock.json` — les jobs CI api passent au pattern racine (`npm ci` + `npm run -w api …`, comme web) et l'audit prod couvre tout le workspace ; `engines.node` corrigé `>=14` → **`>=18`** (les bundles ciblent node18 — un install Node 16 « réussissait » puis cassait au runtime) ; whitelist `files` resserrée — le tarball npm passe de **~14 Mo à 231 Ko** (exit `lib/data/` sources, `build-data.sh`, `extract_animations.py`, dist).
- **Suppression du bundle zombie `lib/engine.mjs` + `shared/src/cli.ts`** (nettoyage post-audit). L'adaptateur stdin/JSON (124K, le plus gros des 3 bundles) servait exclusivement au pont bash supprimé en R3d-6 — plus aucun appelant runtime (les entrypoints `statusline.mjs`/`pokemon.mjs` embarquent le moteur en process). Supprimés : le bundle, sa source `cli.ts` (382 l, dont `derive`), son test de contrat `cli-derive.test.ts`, sa copie à l'install/update (et `update.mjs` nettoie le `engine.mjs` legacy des installs existantes), son étape de build et ses drift-checks CI. `render-engine-parity.bats` est retargeté sur le vrai entrypoint (`node pokemon.mjs <view>` vs les fixtures gelées) — un test plus end-to-end qu'avant.
- **Suppression de bash du runtime — R3 terminé** (Phase R3d-6b — refonte). Le test full-Node étant vert, les scripts bash du runtime sont supprimés : `lib/{lib,statusline,pokemon-status}.sh` + `bin/{install,update,uninstall,status,export,import}.sh`. `bin/claude-pokemon` n'a plus de fallback `.sh` ; `install.mjs`/`update.mjs` ne copient plus de `.sh`. Restent uniquement les outils **mainteneur** (`lib/build-data.sh`, `scripts/build-sprites.sh`, `scripts/ci-pre-push.sh`). **Le CLI est 100 % Node.**
- **Refonte de la suite de tests post-bash** : les ~20 bats qui validaient `engine vs bash` (différentiels de migration) ou testaient le CLI bash sont supprimés ; leur rôle est terminé. La couverture est désormais : **vitest shared** (113, logique moteur), `render-engine-parity.bats` (moteur vs fixtures R3a gelées), nouveau **`golden-node.bats`** (snapshots de sortie des entrypoints Node — vues riches, recap, statusline, notice — régénérables via `CAPTURE=1`), `install-node.bats` + `no-bash.bats` (CLI Node bout-en-bout). CI : shellcheck/install-dry-run ajustés (plus de `.sh` runtime).

Vérifié par `tests/cli/pokemon-dispatch.bats` : différentiel byte-exact `pokemon.mjs` vs `pokemon-status.sh` (engine) sur 23 cas couvrant chaque branche (vues, alias, défaut→main, mutations, RNG, config, réseau mocké, arena, stats-share) — stdout **et** effets state/data. `pokemon-status.sh` reste la commande enregistrée (bascule en piece 5). Vérifié par `tests/cli/statusline-bridge.bats` (différentiel **non strippé**, horloge épinglée, RNG neutralisée par les données — 8 cas : layouts, shiny, flash d'évolution, jauge, sans pourcentage) + 10 tests unitaires vitest. `statusline.sh` reste la commande enregistrée (la bascule + l'auto-submit suivront) ; bundle drift-checké en CI. Les wrappers de rendu de ces 3 commandes mutantes (titre + validation des args + message de résultat) passent par une nouvelle commande moteur générique `cmd <name>` (`shared/src/commands.ts`) — la transformation d'état elle-même était déjà partagée (`collection.ts`). Le pont bash `_cmd` exécute validate+mutate+render en un appel, écrit l'état retourné (gardé non-vide/non-null) sous `flock`, puis imprime la sortie ; exit 3 du moteur (commande non encore portée) → fallback `view_*`. - **`login` / `logout` CLI portés en TypeScript** (Phase R3d-4b — refonte). Le device-flow GitHub (`shared/src/auth.ts`) tourne désormais dans le moteur : `runLogin` fait la requête device-code, la boucle de polling (gestion `authorization_pending` / `slow_down` / abort / timeout 5 min) et l'échange de session, puis **streame son texte vers stderr** (que bash laisse attaché au tty, donc l'invite s'affiche live) et n'émet que l'op `session` sur stdout ; `runLogout` fait la révocation best-effort + l'op `clear`. Le moteur **ne touche jamais** le fichier `.session` (même contrat chmod-600 que l'`arena_secret`) — bash persiste le token / efface le fichier via l'op. `_login`/`_logout` portent leur propre fallback vers `view_login`/`view_logout` (le code de sortie de `login` est signifiant — `|| view_login` rejouerait tout le flow sur un échec normal). Le **happy path du polling** (impossible à tester en bats : GitHub réel + auth humaine) est couvert par 10 tests vitest `shared` (fetch mocké + sleep/now injectés) — meilleure couverture que les smoke tests bash d'origine ; `tests/cli/auth-bridge.bats` diffe les chemins de garde offline byte-exact moteur-vs-bash + la révocation/clear. **Reste R3d-5** : point d'entrée Node + sprites pré-rendus → suppression de bash → Windows natif.
- **Live PvP CLI porté en TypeScript** (Phase R3d-4b — refonte). `/pokemon arena live` (invite / accept / status / move / forfeit) passe par le moteur (`shared/src/live.ts`) : fetch Node + rendu HP/état + la table de moves par stade (hint d'affichage — le worker re-valide). `runLive` est branché dans la commande `arena` du moteur (porte enabled/secret avant délégation, comme bash) ; le secret arène reste géré par bash via l'op `secret`. **Byte-identique** au rendu bash, vérifié par `tests/cli/live-bridge.bats` (mock worker à routage de chemin pour les 5 sous-commandes + parité du moveset charizard + persistance de `last_live_battle_id`). Restent en R3d : `login`/`logout`, puis R3d-5 (point d'entrée Node + sprites pré-rendus → suppression de bash → Windows natif).

Les 2 dernières vues déterministes sont reproduites en TS → **9/9 vues portées**, toutes byte-identiques au rendu bash. `trainer-card` : carte de dresseur (pseudo/anonyme + marque shiny, compagnon Eevee-aware, stats lifetime, badges, statut stats-share, placeholder arena) — helper `lineageEmoji`. `recap` : récap de session — le chemin déterministe (aucune session active) est figé par les fixtures ; le chemin session (durée, deltas XP/amitié/tokens, progression de niveau, événements, évolutions, badges) dépend de l'horloge → `nowEpoch` injecté dans le contexte (l'entrée bash le fournira en R3d), vérifié par un test unitaire vitest **et** un différentiel byte-exact contre le vrai bash via un shim `date`. - **Vue CLI `main` portée en TypeScript** (Phase R3c slice 3 — refonte). La vue principale `/pokemon` (la plus dense) est reproduite en TS, **byte-identique** au rendu bash → **7/9 vues**. - **Vues CLI portées en TypeScript — `pokedex` + `stats`** (Phase R3c slice 2 — refonte). Suite du port : la vue `stats` (statistiques de vie + multiplicateurs + statut fatigué + charme chromatique) et la vue `pokedex` (liste des lignées + grille sauvage 4-colonnes sur 251 entrées, triée par n° national) sont reproduites en TS, **byte-identiques** au rendu bash (4 scénarios + branches non couvertes par les fixtures vérifiées séparément contre le vrai bash). Deux primitives ajoutées : `padChars` (padding par **nombre de caractères**, comme `pokemon_t_pad`/`wc -m`, distinct du padding par octets de `%-Ns`) et `fmtInt` (séparateur de milliers espace). **Fidélité accrue de `printf.ts`** : il modélise désormais la **troncature de bash sur conversion invalide** (un `%` orphelin issu d'un `%%` résolu puis réinjecté dans un autre printf arrête la sortie) — reproduit exactement le quirk de `stats.tired_warning`. `PORTED_VIEWS` du test de parité étendu (6/9 vues). Restent : `main`, puis `recap` + `trainer-card`.
- **Vues CLI portées en TypeScript — liste box-free** (Phase R3c — refonte, ADR-006/007). Première tranche du port de la coquille : les vues `badges`, `inventory`, `team`, `pc` sont reproduites en TS (`shared/src/render/`) **byte-identiques** au rendu bash. ### Changed

### Fixed

- **Système XP refondu** (3 bugs corrigés + recalibration courbe).
  (1) **Per-tick delta** remplace le high-water mark cassé : `pokemon_tick` calculait `delta = current − max_ever_for_session`, donc une fois le pic de contexte atteint, plus aucune XP ne tombait tant qu'on ne le dépassait pas — et l'auto-compaction de Claude Code rendait ça quasi-impossible. Nouveau : `delta = current − last_tick_tokens`. Chaque interaction qui fait croître le contexte donne du XP, et l'auto-compaction ne bloque plus le flux. Migration douce : `last_tick_tokens` se seed depuis l'ancien `max_context_tokens`, pas de windfall.
  (2) **Détection 1M context** : `statusline.sh` fallback hardcodé à 200K plafonnait les users Opus 4.7 / Sonnet 4.6 1M. Détection via `model.display_name` ("1M context" / "(1M)") → `default_window=1,000,000`.
  (3) **Anti-spike cap 10K tokens/tick** : empêche un seul gros message (lecture de N fichiers volumineux) de clearer plusieurs niveaux. `raw_delta` reste non-capé pour le badge centurion 100M tokens.

- **Courbe XP recalibrée** (anchors `1 jour = 1 éclosion` + `1 semaine = Reptincel pour devs normaux`). Two-phase géométrique : ratio 1.205 Lv.1→16, puis 1.05 Lv.16→100. Ancres :

  | Niveau | XP | Dev normal (600K XP/j) |
  |---|---|---|
  | Lv.1 (œuf éclos) | 300K | ~0.5 jour |
  | Lv.5 | 635K | ~1.3 jours |
  | Lv.16 (Reptincel) | 5M | ~8 jours ≈ 1 semaine |
  | Lv.36 (Dracaufeu) | 13.2M | ~3 semaines |
  | Lv.100 (champion) | 300M | ~1.5 an |

  Pas de daily cap : la difficulté est gérée par la courbe seule. Heavy devs (500K+ tokens/j) progressent naturellement plus vite, casual users plus lentement — pas de plafond artificiel qui frustre les sessions intenses. Force-propagée via update.sh.

- **Affichage statusline relatif au niveau** : la barre XP affichait `Lv.13 904.4K/983.6K 24%` (cumulé absolu) — peu lisible et différent de la convention des jeux Pokémon. Maintenant `Lv.13 26K/79K 24%` : XP **dans** le niveau / XP nécessaire pour le niveau suivant. Total cumulé reste visible via `/pokemon` (vue principale) et la trainer card.
